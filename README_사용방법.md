# 디스플레이 구조분석 측정값 자동 정리 v2.1.0

## 1. 무엇을 하는 프로그램인가

FIB·SEM·단면 분석 이미지에 표시된 `428.0 nm`, `56.85 µm`, `15.2°` 같은
측정값을 찾아 검토한 뒤 Excel 표로 정리합니다. `H1=167.5nm`,
`Top-W:2.35um`처럼 포인트명과 값이 함께 있으면 포인트명도 열 이름으로 사용합니다.

v2는 이전 버전의 **고정된 측정영역(ROI)** 방식을 사용하지 않습니다. 이미지마다
값의 위치와 개수가 달라도 이미지 전체에서 측정선과 값 후보를 다시 찾습니다.

- 이미지 한 장당 Excel 한 행
- `nm`, `µm/um`은 높이 그룹, `°/deg`는 각도 그룹으로 분리
- 샘플 이미지에서 사용자가 높이·각도 그룹의 앞뒤 순서 지정
- 같은 그룹 안에서는 위→아래, 같은 높이면 왼쪽→오른쪽 순서
- 포인트명이 있으면 같은 이름끼리 열 매칭, 없으면 이미지 위치로 매칭
- 수치값은 숫자 셀로 저장하고 단위는 열 제목에 표시
- `428.0`, `1.2300`처럼 원본에 표시된 소수 자릿수 보존
- 이미지별 측정값 개수가 달라도 처리
- 표의 마지막 행에 열별 평균 수식 표시
- 하단 스케일바·장비정보 후보는 기본 제외
- 후보 이미지와 모든 측정 위치를 사용자가 최종 선택·수정
- 인터넷 OCR API를 사용하지 않고 회사 PC 내부에서 처리

## 2. v2.1에서 추가된 기능

| 입력 예 | 인식 결과 |
|---|---|
| `H1=167.5nm` | 포인트명 `H1`, 값 `167.5`, 단위 `nm` |
| `Top-W(2.35um)` | 포인트명 `Top-W`, 값 `2.35`, 단위 `µm` |
| `Gate_1:573.1 µm` | 포인트명 `Gate_1`, 값 `573.1`, 단위 `µm` |
| `A1 15.2deg` | 포인트명 `A1`, 값 `15.2`, 단위 `°` |
| `284.2nm` | 포인트명 없음, 값 `284.2`, 단위 `nm` |

한 이미지에 위 형식들이 섞여 있어도 처리합니다. 포인트명은 영문으로 시작하고
영문·숫자·하이픈(`-`)·언더바(`_`)를 사용할 수 있습니다. 값이 포인트명보다 먼저
나오는 형식은 포인트명 없는 값으로 처리합니다.

## 3. 이전 고정영역 버전과 달라진 점

| 항목 | 이전 방식 | v2 방식 |
|---|---|---|
| 위치 | 사용자가 지정한 고정 박스만 검사 | 이미지 전체에서 측정선을 다시 검출 |
| 값 개수 | 기준 이미지와 같은 개수에 적합 | 이미지마다 0개~여러 개 가능 |
| OCR 호출 | 위치마다 여러 전처리 × Tesseract 실행 | RapidOCR를 한 번 로드한 뒤 메모리에서 반복 인식 |
| 추가 설치 | Tesseract 프로그램 별도 설치 | Tesseract 불필요, Python 패키지만 설치 |
| 오류 처리 | 누락 가능 | 읽지 못해도 위치 후보를 남겨 사용자가 수정 |
| 스케일바 | ROI에 따라 달라짐 | 하단 후보 기본 제외 + 검토 화면에서 복원 가능 |

## 4. 가장 쉬운 설치·실행 방법

1. 압축파일을 회사 PC의 새 폴더에 풉니다.
2. `RUN_APP.bat`를 더블클릭합니다.
3. 필요한 Python 패키지가 없으면 자동으로 설치한 뒤 프로그램이 열립니다.

VSCode에서는 압축을 푼 폴더를 열고 `START_HERE.py`의 **Run Python File** 버튼을
눌러도 됩니다.

터미널에서 직접 실행할 때는 다음 한 줄만 입력하면 됩니다.

```powershell
py START_HERE.py
```

`Tesseract OCR`은 설치하지 않습니다. 최초 Python 패키지 설치에는 회사망에서
Python 패키지 저장소 접속 권한이 필요합니다. 회사 보안정책에서 허용된 저장소를
사용하세요. 한 번 설치된 뒤 실제 이미지 판독은 로컬 모델 파일로 수행됩니다.

`RUN_APP.bat`와 `START_HERE.py`는 설치 누락 여부를 확인하고 Python 패키지 설치를
시도합니다. 회사망이 Python 패키지 저장소까지 차단하면 자동 설치도 실패하므로,
그 경우 사내 승인 저장소 또는 IT 담당자의 오프라인 패키지 설치가 필요합니다.

## 5. 실제 사용 순서

1. `이미지 파일 추가` 또는 `폴더 추가`를 누릅니다.
2. 기본값인 빠른 검사를 먼저 사용합니다.
   - 글자가 흑백이거나 자동 검출이 부족하면 `정밀 재검증(느림)`을 켭니다.
3. `전체 검사`를 누릅니다.
4. `후보·값 검토`에서 사용할 이미지와 측정값을 확인합니다.
5. 대표 이미지에서 높이 또는 각도 항목을 선택하고 `그룹 위로/그룹 아래로`를 눌러
   원하는 그룹 순서를 정합니다.
   - 예: `각도 → 높이` 또는 `높이 → 각도`
   - 같은 그룹 안에서는 위→아래, 같은 높이면 왼쪽→오른쪽으로 자동 정렬됩니다.
6. `현재 그룹 순서를 기준으로 설정`을 누릅니다.
   - 포인트명이 있는 값은 다른 이미지의 같은 포인트명과 같은 열에 배치됩니다.
   - 포인트명이 없는 값은 같은 그룹 안의 가까운 위치와 매칭됩니다.
   - 기준 이미지에 없던 새 포인트나 위치는 해당 그룹의 새 열로 추가됩니다.
7. 노란색 `확인 필요` 항목을 더블클릭해 포인트명·숫자·단위를 수정합니다.
8. 자동 검출되지 않은 값은 `누락 위치 추가`를 누른 뒤 이미지에서 위치를 클릭합니다.
9. 스케일바처럼 필요 없는 값은 `값 사용 전환`으로 제외합니다.
10. `검토 완료` → `Excel 저장`을 누릅니다.

같은 이미지 안에서 같은 포인트명이 두 번 검출되면 두 항목 모두 `확인 필요`로
표시됩니다. 실제 중복이 아니라 OCR 오류라면 포인트명을 수정하세요.

## 6. 검토 화면의 의미

- 초록색 상자: 숫자와 단위가 정상 판독된 위치
- 주황색 상자: 숫자 누락, 낮은 신뢰도 또는 전처리별 결과 불일치
- 회색 상자: Excel에서 제외할 위치
- 파란색 상자: 현재 선택한 위치

글자가 너무 흐리면 프로그램은 숫자를 억지로 추측하지 않습니다. 위치 상자는 남기고
수치 셀을 비워 두므로 사용자가 원본을 보고 입력할 수 있습니다.

## 7. 생성되는 Excel

### 측정 데이터

- 이미지 한 장당 한 행
- 포인트명이 있으면 `H1 (nm)`, `A1 (°)`처럼 열 제목에 표시
- 포인트명이 없으면 `높이 1 (nm)`, `각도 1 (°)`처럼 자동 이름 사용
- 높이와 각도 열은 사용자가 정한 그룹 순서대로 서로 섞이지 않게 배치
- 데이터 셀에는 계산 가능한 숫자만 저장
- 마지막 행에 `AVERAGE` 평균 수식 저장
- `nm`와 `µm`는 같은 높이 그룹이지만 자동 환산하지 않고 각 열의 원래 단위를 유지
- 같은 열의 단위가 이미지마다 섞이거나 위치 매칭이 불안정하면 잘못된 평균을 만들지 않고
  `단위 확인 필요` 또는 `위치 확인 필요`로 표시

### 전체 검출 목록

모든 후보의 수치, 단위, OCR 원문, 신뢰도, 검출 방식, 좌표, 포함 여부를 기록합니다.

### 검토 필요

누락·저신뢰도·제외 후보만 모아 원본 대조 대상을 쉽게 확인할 수 있습니다.

### 설정 정보

프로그램/OCR 버전, 선택 이미지 수, 기준 이미지, 로컬 처리 방식을 기록합니다.

## 8. 파일명 권장 규칙

가장 안전한 형식은 `<시료번호>-<이미지순번>.<확장자>`입니다.

```text
1-01.png
1-02.png
2-01.tif
2-02.tif
```

규칙을 판별하지 못하는 파일도 검사하지만, 이때 시료명은 폴더명, 이미지 순번은
정렬 순서로 임시 입력되고 화면에 `*` 표시가 붙습니다.

## 9. 보안 관련

- 이미지 파일과 OCR 결과를 웹 API에 업로드하는 코드가 없습니다.
- RapidOCR의 ONNX 모델 경로를 로컬 파일로 고정합니다.
- ONNX Runtime 초기화 전에 `ORT_DISABLE_TELEMETRY=1`을 설정합니다.
- 로컬 모델이 누락되면 인터넷에서 자동으로 받지 않고 오류로 중단합니다.
- Excel에 VBA 매크로를 넣지 않습니다.
- 원본 이미지는 읽기만 하며 수정·삭제하지 않습니다.

사내 사용 전에는 Python, RapidOCR, ONNX Runtime 패키지가 회사 보안정책상 허용되는지
확인하세요.

## 10. 알아야 할 한계

- OCR은 어떤 엔진도 100% 정확성을 보장할 수 없습니다.
- 글자 높이가 매우 작거나 압축·초점 문제로 숫자 획이 사라진 이미지는 자동 확정할
  수 없습니다. 이 경우 검토 화면에서 직접 입력해야 합니다.
- 유색 측정선이 없는 흑백 표시는 전체 이미지 OCR로 처리하므로 조금 더 느리고,
  스케일바·장비정보가 후보로 나타날 수 있습니다.
- 색상 배경 위에 비슷한 색의 글자가 겹치거나 측정선이 끊기면 누락될 수 있습니다.
- 포인트명이 흐리거나 OCR에서 한 글자라도 잘못 읽히면 다른 열로 분리될 수 있으므로
  검토 화면에서 포인트명을 확인해야 합니다.
- 매우 작은 `°` 기호는 누락될 수 있습니다. 가능하면 장비 표기를 `deg`로 출력하거나
  검토 화면에서 단위를 수정하세요.
- 열별 평균이 물리적으로 의미 있으려면 같은 열이 같은 측정 위치를 뜻하는지 사용자가
  기준 순서와 미리보기로 확인해야 합니다.

## 11. 사내 검증 권장 절차

1. 정답을 이미 알고 있는 실제 회사 이미지 20~30장으로 시작합니다.
2. 자동 결과와 기존 수기 결과를 **전수 비교**합니다.
3. 다른 장비, 글자색, 배율, 회전, 이미지 확장자를 모두 포함합니다.
4. 오판독이 하나라도 있으면 해당 조건을 기록해 추가 시험 자료로 사용합니다.
5. 충분한 표본에서 통과한 뒤 본 업무에 적용합니다.
